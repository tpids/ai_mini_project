# RAG·LLM 평가 추가 결과

2026-10-22 작업. 비교 대상은 세 가지 개선과 전날 평가 도구까지 포함한 Git 커밋 `68ddee4`다.
기존 교수님 기본 코드(`741cd7e`)와의 비교 결과도 그대로 보관했다.

## 추가한 기능

1. **RAG 매뉴얼 검색**: 서비스별 관측 알림을 실제 다국어 의미 벡터로 검색한다.
   기존 규칙이 찾은 모든 필수 매뉴얼을 보존하고, 정상 서비스·모호한 검색·검색 장애에서는 기존 보호 동작을 유지한다.
2. **LLM-as-a-Judge**: 저장된 답변과 실제 수집 근거를 로컬 모델로 대조한다.
   수치·상태, 매뉴얼 조건, 불확실성, 서비스 연결을 0~2점으로 채점하고 이유와 답변 원문 줄을 기록한다.
   답변 수정·통과 승인·복구 조치에 사용하지 않는다.

## 기존 기능 유지 확인

[기존 14개 사례 반복 비교](eval_runs/20261022_091516_8d83b3_fake/report.md)는 생성·계획 모의 모델과 실제 임베딩을 사용했다.
각 사례를 세 번 실행하고 워밍업 한 번을 제외했다.

| 지표 | RAG 추가 전 | RAG 추가 후 |
|---|---:|---:|
| 대상 선택 | 45/45 | 45/45 |
| 필요 매뉴얼 조회 | 33/33 | 33/33 |
| 실행 오류 | 0 | 0 |

RAG 검색 30회가 성공했고, 검색 오류로 규칙에 대체한 경우는 0회다.
이 점수는 실제 생성 LLM의 전체 정확도를 뜻하지 않는다.

## 기존 규칙 밖의 알림 표현

[별도 8개 사례 비교](eval_runs/20261022_091748_0af3ff_fake/report.md)는 알림 표현 6종과 모호한 알림 2종으로 구성했다.
생성·계획은 모의 모델이며 검색은 실제 `embeddinggemma`다. 각 사례 3회, 워밍업 1회를 사용했다.

| 지표 | RAG 추가 전 | RAG 추가 후 |
|---|---:|---:|
| 대상 선택 | 24/24 | 24/24 |
| 필요 매뉴얼 조회 | 0/18 | 15/18 (83.3%) |
| 불필요한 매뉴얼 조회 | 0 | 0 |

CPU·디스크·지연·네트워크·DB 표현은 매뉴얼을 찾았다.
객체 회수와 점유 공간 누적을 설명한 메모리 표현은 최고 유사도 0.355로 기준 0.40보다 낮아 보류했다.
모호한 알림 두 유형에는 매뉴얼을 강제로 붙이지 않았다.
소규모 개발용 사례이며, 다양한 운영 표현에 대한 검색 정확도로 일반화하지 않는다.

## 실제 로컬 생성 모델 비교

payments/cache 복수 진단과 web/auth 진단을 각 3회 측정하고 워밍업 한 번을 제외했다.

각 버전 3건이며 `qwen3:8b`, 프롬프트 v3를 사용했다. 생성 때의 답변·수집 근거는 변경하지 않았다.

이 점수는 LLM의 판단이지 사실의 정답률이 아니다.

### 평가자 자체의 한계

[최종 v3 대조 예제](judge_checks/20261022_093529_bf2541/checks.json)에서 정상 답변은 모두 2점,
현재 CPU를 97.2%에서 13.8%로 바꾼 답변은 수치 0점을 받았다.
조건 삭제·미확인 실행 주장에는 조건 1점을 주었지만, 허위 로그 확인·원인 단정은 불확실성 2점으로 놓쳤다.
평가자가 선택한 인용 줄이 평가 이유를 충분히 뒷받침하는지도 사람이 확인해야 한다.
따라서 Judge로 기존 원문 검증을 대체하지 않는다. 이 예제는 개발용 점검이며 독립적인 일반화 성능 평가가 아니다.

## 재실행과 적용

현재 컴퓨터에는 임베딩 모델과 인덱스 준비가 끝났다.
기존 `bash sh/run_agent_ollma.sh`로 실행하면 v2의 Ollama 백엔드에서 RAG가 기본 활성화된다.
`RAG_ENABLED=0`으로 기존 규칙 방식만 사용할 수도 있다.
평가·Judge 실행 명령과 구조는 [구현 설명](RAG_JUDGE.md)에 정리했다.


## 채팅 답변별 평가 연결

최종 답변과 당시 수집 근거를 함께 저장하고, 그 답변 아래의 **이 답변 평가** 버튼으로 직접 채점할 수 있게 추가했다.
HTTP와 스트리밍 모두 동일한 스냅샷을 사용한다. 채점할 때 진단을 재실행하거나 원래 답변을 수정하지 않는다.
이 기능 이전에 생성한 채팅에는 근거 스냅샷이 없으므로 질문을 다시 보내야 한다.
과거 전후 평가 파일을 지정하는 CLI와 채팅 화면의 단건 평가를 구분한다.

단건 평가 화면도 별도 테스트 브라우저에서 실제 로컬 LLM으로 확인했다. 네 항목 표시, 채점 전후 답변 불변, 브라우저 오류 없음까지 확인했다. 테스트 화면의 생성·계획은 모의 모델이며 사용자 채팅 서버와 별도 포트를 사용했다.
